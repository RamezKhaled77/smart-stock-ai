# SmartStock AI — دليل المستخدم

**الإصدار:** v1

دليل مبسط يشرح كيفية استخدام SmartStock AI، بداية من تشغيل البرنامج وإضافة المنتجات، وصولًا إلى تسجيل المبيعات وتحليلها والتنبؤ بالطلب واقتراح المنتجات التي تحتاج إلى إعادة تخزين.

الدليل موجه لأي شخص سيستخدم المشروع، ولا يحتاج إلى معرفة بالبرمجة.

---

## 1. ما هو SmartStock AI؟

SmartStock AI هو تطبيق يساعد أصحاب المحلات التجارية الصغيرة على إدارة المنتجات والمخزون والمبيعات من مكان واحد.

بدل ما تتابع المنتجات والكميات والمبيعات يدويًا في أكثر من ملف، التطبيق يجمع العمليات دي في مكان واحد.

يمكنك من خلاله:

- تسجيل المنتجات التي يبيعها المتجر ومعرفة الكمية المتاحة من كل منتج.
- تسجيل كل عملية بيع، مع تحديث كمية المخزون تلقائيًا.
- عرض رسوم بيانية تساعدك على فهم حركة المبيعات.
- توقع حجم الطلب على المنتجات خلال الأيام السبعة أو الأربعة عشر أو الثلاثين القادمة.
- الحصول على اقتراحات توضح المنتجات التي قد تحتاج إلى إعادة تخزين، والكمية المقترحة.

### نقطتان مهمتان

1. **التطبيق يقدم اقتراحات، ولا ينفذ عمليات شراء.** لن يقوم التطبيق بطلب المنتجات من الموردين أو تغيير المخزون من تلقاء نفسه. القرار النهائي للمستخدم.
2. **التوقعات تقديرية وليست مضمونة.** لو التطبيق توقع بيع 30 وحدة الأسبوع القادم، فهذا تقدير مبني على المبيعات السابقة، وليس وعدًا بأن هذا العدد سيُباع بالفعل.

## 2. البدء في استخدام التطبيق

### 2.1 المتطلبات

لتشغيل المشروع تحتاج إلى:

- جهاز كمبيوتر.
- تثبيت Python 3.12.
- وجود مجلد المشروع SmartStock AI على الجهاز.

### 2.2 تجهيز المشروع لأول مرة

افتح Terminal (الطرفية التي نستخدمها لكتابة الأوامر) داخل مجلد المشروع، ونفذ الأوامر التالية بالترتيب:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

شرح سريع:

- `venv`: بيئة افتراضية، وهي مساحة منفصلة يتم تثبيت مكتبات المشروع بداخلها حتى لا تختلط بمكتبات مشاريع أخرى.
- `.venv`: اسم المجلد الذي يحتوي على هذه البيئة.
- `pip`: الأداة المسؤولة عن تثبيت مكتبات Python.
- `requirements.txt`: ملف يحتوي على قائمة المكتبات التي يحتاج إليها المشروع.

### 2.3 تشغيل التطبيق

في كل مرة تريد فيها تشغيل المشروع، افتح Terminal داخل مجلد المشروع ونفذ:

```bash
.venv/bin/python -m streamlit run app.py
```

بعدها سيفتح التطبيق في المتصفح تلقائيًا، وغالبًا سيكون عنوانه:

`http://localhost:8501`

**ما معنى Localhost؟**

يعني أن التطبيق يعمل على جهازك أنت، وليس منشورًا على الإنترنت. يمكنك استخدامه من خلال المتصفح، لكن بياناته تظل محفوظة محليًا على جهازك.

### 2.4 أين يتم حفظ البيانات؟

دي من أهم النقاط التي يجب فهمها.

التطبيق يستخدم SQLite، وهي قاعدة بيانات بسيطة تحفظ البيانات في ملف واحد بدلًا من الحاجة إلى Database Server منفصل.

مكان قاعدة البيانات:

`data/smartstock.db`

**ما معنى Database؟**

هي المكان المنظم الذي يحتفظ فيه التطبيق بالمعلومات، مثل:

- المنتجات.
- الكميات الموجودة في المخزون.
- المبيعات المسجلة.
- بيانات المبيعات التاريخية التي تم استيرادها.

**ما معنى Storage؟**

هو المكان الذي يتم فيه تخزين البيانات فعليًا. في مشروعنا، البيانات يتم حفظها داخل ملف قاعدة البيانات الموجود في مجلد `data`.

يتم إنشاء ملف قاعدة البيانات تلقائيًا عند أول تشغيل للتطبيق.

**كيف أحتفظ بنسخة احتياطية من بياناتي؟**

يمكنك ببساطة نسخ الملف:

`data/smartstock.db`

وحفظ نسخة منه في مكان آمن.

هذه العملية تسمى Backup، أي إنشاء نسخة احتياطية يمكن الرجوع إليها إذا حدثت مشكلة في الملف الأصلي.

> مهم: لا تخلط بين ملف قاعدة البيانات وملفات Dataset. قاعدة البيانات تحتوي على بيانات تشغيل التطبيق، أما Dataset فهي بيانات المبيعات التاريخية المستخدمة في التحليل والتوقعات.

### 2.5 تجهيز نظام التوقعات لأول مرة

ميزة Demand Forecasting تحتاج إلى Model تم تدريبه مسبقًا.

**ما معنى Model؟**

هو نموذج تعلم آلي (Machine Learning Model)، يتعلم الأنماط الموجودة في بيانات المبيعات السابقة، ثم يستخدمها لتقدير الطلب في المستقبل.

إذا كان ملف البيانات التاريخية موجودًا في:

`data/raw/train.csv`

نفذ الأمر التالي لتدريب النموذج:

```bash
PYTHONPATH=src .venv/bin/python scripts/train_model.py
```

التدريب يتم مرة واحدة عند تجهيز المشروع، ويمكن إعادة التدريب عند الحاجة.

إذا لم يتم تدريب النموذج بعد، ستظل باقي وظائف التطبيق تعمل بشكل طبيعي، لكن ميزة التوقعات لن تكون متاحة.

### 2.6 الوضع الفاتح والداكن

يمكنك تغيير شكل التطبيق من:

Menu (الثلاث نقاط أعلى اليمين) → Settings → Theme

ثم اختيار:

- Light: الوضع الفاتح.
- Dark: الوضع الداكن.
- Use system setting: استخدام الوضع الموجود على جهازك.

لا تحتاج إلى إعادة تشغيل التطبيق بعد تغيير الوضع.

## 3. مصطلحات مهمة ستقابلها

| المصطلح | معناه ببساطة |
|---|---|
| Product | المنتج الذي يبيعه المتجر. |
| SKU | كود مميز لكل منتج، مثل `TSHIRT-BLU`. لا يمكن أن يشترك منتجان في نفس الكود. |
| Stock | كمية المنتج الموجودة حاليًا في المخزون. |
| Lead Time | المدة التي يحتاجها المورد لتوصيل المنتج بعد طلبه، محسوبة بالأيام. |
| Safety Stock | كمية إضافية نحتفظ بها احتياطيًا لتجنب نفاد المنتج بشكل مفاجئ. |
| Average Daily Demand | متوسط عدد الوحدات التي يتم بيعها يوميًا، بناءً على آخر فترة من سجل المبيعات تصل إلى 30 يومًا. الأيام التي لم تحدث فيها مبيعات تُحسب بصفر. |
| Reorder Point | الحد الذي عندما يصل إليه المخزون أو يقل عنه، يجب التفكير في إعادة طلب المنتج. |
| Dataset Item | رقم المنتج داخل ملف بيانات المبيعات التاريخية المستورد. نربط هذا الرقم بالمنتج داخل التطبيق حتى يمكن عمل توقعات له. |
| Forecast Horizon | الفترة المستقبلية التي نريد توقع الطلب خلالها: 7 أو 14 أو 30 يومًا. |

## 4. شرح صفحات التطبيق

القائمة الجانبية Sidebar هي المكان الذي يمكنك من خلاله التنقل بين صفحات التطبيق.

الصفحات مقسمة إلى مجموعات:

- Overview: نظرة عامة.
- Inventory: إدارة المنتجات والمخزون.
- Sales: إدارة المبيعات وتحليلها.
- Forecasting: توقع الطلب.
- Data: استيراد البيانات التاريخية.

### 4.1 Dashboard — لوحة التحكم

**المسار:** Sidebar → Overview → Dashboard

الـ Dashboard هي الصفحة التي تعطيك نظرة سريعة على حالة المتجر.

#### البطاقات الموجودة في الأعلى

- **Active Products:** عدد المنتجات النشطة التي يبيعها المتجر حاليًا.
- **Total Stock:** إجمالي عدد الوحدات الموجودة في المخزون لجميع المنتجات.
- **Products Needing Reorder:** عدد المنتجات التي وصلت كميتها إلى Reorder Point أو أصبحت أقل منه.

#### البطاقات الموجودة في الصف الثاني

- **Units Sold (Last 7 Days):** عدد الوحدات التي تم بيعها خلال آخر 7 أيام.
- **Sales Recorded (Last 7 Days):** عدد عمليات البيع المسجلة خلال آخر 7 أيام.
- **Top Seller (30 Days):** المنتج الأكثر مبيعًا خلال آخر 30 يومًا، بناءً على عدد الوحدات.

#### الأقسام الموجودة أسفل البطاقات

1. **Sales Trend:** رسم بياني خطي يوضح عدد الوحدات المباعة يوميًا. يمكنك التبديل بين آخر 7 أيام وآخر 30 يومًا.
2. **Top Sellers — Last 30 Days:** جدول مرتب يعرض المنتجات الأكثر مبيعًا خلال آخر 30 يومًا.
3. **Low-Stock Overview:** يعرض المنتجات التي حالتها Low Stock أو Out of Stock، مع الكميات المقترحة للطلب. إذا كانت كل المنتجات متوفرة بشكل جيد، ستظهر رسالة توضح ذلك.
4. **Forecast Readiness:** يوضح عدد المنتجات التي يمكن عمل توقعات لها بالفعل. يجب أن يكون المنتج مرتبطًا بـ Dataset Item حتى يصبح مؤهلًا للتوقع.

**ملحوظة:** الـ Dashboard مخصصة لعرض المعلومات فقط (Read-only)، وليست مكانًا لتنفيذ العمليات أو تعديل البيانات.

### 4.2 Products & Inventory — إدارة المنتجات والمخزون

**المسار:** Sidebar → Inventory → Products & Inventory

هذه الصفحة هي المكان الأساسي لإدارة المنتجات وكميات المخزون.

تحتوي على أربعة Tabs (علامات تبويب):

#### أولًا: Product List — قائمة المنتجات

تعرض جدولًا يحتوي على المنتجات النشطة، ومع كل منتج معلومات مثل:

- الاسم.
- SKU.
- Category (التصنيف).
- Stock (الكمية المتاحة).
- Lead Time.
- Safety Stock.
- Reorder Point.
- Average Daily Demand.
- Status (حالة المخزون).

حالات المخزون:

| الحالة | معناها |
|---|---|
| In Stock | كمية المنتج أعلى من Reorder Point، وبالتالي المخزون في حالة جيدة. |
| Low Stock | كمية المنتج أكبر من صفر، لكنها وصلت إلى Reorder Point أو أقل منه. يجب التفكير في إعادة الطلب. |
| Out of Stock | كمية المنتج أصبحت صفرًا، أي أن المنتج نفد من المخزون. |

يمكنك البحث باستخدام اسم المنتج أو SKU، كما يمكنك استخدام Filters (فلاتر) لتصفية المنتجات حسب Category أو Stock Status.

#### ثانيًا: Add Product — إضافة منتج

يمكنك من خلالها إضافة منتج جديد.

الحقول:

- **Name:** اسم المنتج، وهو مطلوب.
- **SKU:** كود المنتج، وهو مطلوب ويجب أن يكون فريدًا.
- **Category:** تصنيف المنتج، وهو اختياري.
- **Initial Stock:** كمية المنتج الموجودة حاليًا عند إضافته. القيمة الافتراضية صفر.
- **Lead Time:** مدة وصول المنتج من المورد. القيمة الافتراضية 3 أيام.
- **Safety Stock:** كمية الأمان الإضافية. القيمة الافتراضية صفر.

#### ثالثًا: Edit Product — تعديل منتج

تستخدم لتعديل بيانات منتج موجود، مثل الاسم والتصنيف وLead Time وSafety Stock.

يوجد أيضًا إجراءان مهمان:

**Deactivate Product — إيقاف المنتج**

التطبيق يستخدم Soft Delete بدلًا من الحذف النهائي.

**ما معنى Soft Delete؟**

يعني إيقاف المنتج وإخفاءه من القوائم العادية ومن عمليات البيع، لكن دون مسح بياناته من قاعدة البيانات.

بالتالي:

- لن يظهر المنتج ضمن المنتجات النشطة.
- لن يمكن تسجيل مبيعات جديدة له.
- سيظل سجل مبيعاته القديم محفوظًا.
- يمكنك إعادة تفعيله في أي وقت.

يجب تأكيد عملية الإيقاف من خلال تحديد مربع التأكيد أولًا.

**Reactivate Product — إعادة تفعيل المنتج**

إذا اخترت منتجًا تم إيقافه سابقًا، يمكنك إعادته للعمل مرة أخرى.

يوجد في نفس القسم إعداد آخر اسمه:

**Linked Dataset Item**

وهو المسؤول عن ربط المنتج ببيانات المبيعات التاريخية التي سيتم استخدامها في التوقعات. سنشرح ذلك في قسم Data Import وDemand Forecast.

#### رابعًا: Adjust Stock — تعديل المخزون

تستخدم هذه الخاصية لتغيير كمية المخزون لأسباب غير عمليات البيع.

يوجد طريقتان:

**1. Add or Remove Units**

إضافة أو خصم عدد من الوحدات.

أمثلة:

- وصلت شحنة جديدة فيها 20 وحدة: أدخل `+20`.
- تلفت 3 وحدات: أدخل `-3`.
- تحتاج إلى تصحيح الكمية بزيادة أو نقص: أدخل الرقم المناسب.

بعدها اضغط Apply Adjustment.

**2. Set Exact Stock (Correction)**

تحديد الكمية النهائية للمخزون بشكل مباشر.

مثال: التطبيق يعرض أن لديك 15 وحدة، لكن بعد العد الفعلي وجدت أن لديك 12 وحدة.

يمكنك إدخال `12` ليتم استبدال الرقم القديم بالرقم الصحيح.

انتبه: هذه العملية تستبدل الكمية السابقة بالكامل، لذلك استخدمها عند الحاجة إلى تصحيح المخزون فقط. أما التعديلات اليومية، فالأفضل استخدام Add or Remove Units.

**قاعدة مهمة:** لا يسمح التطبيق بأن تصبح كمية المخزون أقل من صفر. أي تعديل يؤدي إلى مخزون سالب سيتم رفضه.

### 4.3 Sales Management — إدارة المبيعات

**المسار:** Sidebar → Sales → Sales Management

تحتوي الصفحة على Tabين:

#### أولًا: Record Sale — تسجيل عملية بيع

لتسجيل عملية بيع جديدة:

1. اختر المنتج الذي تم بيعه. سيظهر مع كل منتج مقدار المخزون المتاح منه.
2. أدخل الكمية المباعة، ويجب أن تكون عددًا صحيحًا لا يقل عن 1.
3. اختر تاريخ البيع. يمكنك تسجيل عملية بيع بتاريخ سابق، مثل بيع حدث أمس وتقوم بتسجيله اليوم، لكن لا يمكنك اختيار تاريخ في المستقبل.
4. اضغط Record Sale.

بعد تسجيل البيع:

- يتم تسجيل العملية في قاعدة البيانات.
- يتم خصم الكمية المباعة من المخزون تلقائيًا.
- تظهر رسالة تأكيد توضح نجاح العملية والكمية المتبقية.

#### كيف يتعامل التطبيق مع نقص المخزون؟

إذا حاولت بيع كمية أكبر من الكمية الموجودة، سيرفض التطبيق العملية.

مثلًا: لديك 5 وحدات، وحاولت تسجيل بيع 8 وحدات.

سيحدث الآتي:

- لن يتم تسجيل عملية البيع.
- لن يتم تغيير المخزون.
- ستظهر رسالة توضح الكمية المطلوبة والكمية المتاحة.

الحل الصحيح هو تسجيل وصول كمية جديدة من خلال Adjust Stock أولًا.

كذلك المنتجات التي تم إيقافها لا تظهر ضمن قائمة المنتجات المتاحة للبيع.

#### ثانيًا: Sales History — سجل المبيعات

يعرض جميع عمليات البيع التي تم تسجيلها.

يمكنك استخدام Filters لتصفية السجل حسب:

- المنتج.
- الفترة الزمنية، من تاريخ إلى تاريخ.

كل عملية بيع تعرض:

- المنتج.
- الكمية.
- تاريخ حدوث البيع.
- تاريخ تسجيل العملية في التطبيق.

**ملحوظة مهمة:** سجلات المبيعات لا يمكن تعديلها أو حذفها. الهدف هو الحفاظ على سجل موثوق للعمليات التي تم تسجيلها.

### 4.4 Sales Analytics — تحليل المبيعات

**المسار:** Sidebar → Sales → Sales Analytics

هذه الصفحة تساعدك على فهم حركة المبيعات خلال فترة معينة.

اختر:

- Start Date: بداية الفترة.
- End Date: نهاية الفترة.
- Product: يمكنك اختيار منتج معين أو ترك الاختيار لعرض كل المنتجات.

بعد ذلك يعرض التطبيق:

#### 1. Summary Cards — بطاقات الملخص

- **Units Sold:** إجمالي الوحدات المباعة.
- **Sales Recorded:** عدد عمليات البيع المسجلة.
- **Avg Units/Day:** متوسط الوحدات المباعة يوميًا، مع احتساب الأيام التي لم تحدث فيها مبيعات بصفر.
- **Days with Sales:** عدد الأيام التي حدثت فيها مبيعات فعلية.

#### 2. Daily Units Sold

رسم بياني خطي يوضح عدد الوحدات المباعة في كل يوم خلال الفترة المحددة.

#### 3. Weekday Pattern

رسم بياني بالأعمدة يوضح متوسط المبيعات في كل يوم من أيام الأسبوع.

يساعدك على اكتشاف أنماط مثل زيادة المبيعات يوم السبت أو انخفاضها يوم الاثنين.

#### 4. Sales by Product

ترتيب للمنتجات حسب عدد الوحدات المباعة، مع توضيح نسبة كل منتج من إجمالي الوحدات.

#### 5. Product Performance

جدول يعرض أداء كل منتج، مثل:

- عدد الوحدات المباعة.
- متوسط البيع اليومي.
- أول عملية بيع وآخر عملية بيع في الفترة.
- Trend: اتجاه المبيعات، ويكون Rising أو Falling أو Stable.

يتم تحديد الاتجاه من خلال مقارنة النصف الأول من الفترة بالنصف الثاني.

#### 6. Monthly Totals

إذا كانت الفترة المحددة تشمل عدة أشهر، يعرض التطبيق جدولًا يوضح إجمالي المبيعات لكل شهر.

#### تنزيل التقارير

يمكنك تنزيل ثلاثة ملفات بصيغة CSV:

- Sales by Product.
- Product Performance.
- Monthly Totals.

**ما هو CSV؟**

هو نوع بسيط من الملفات يمثل البيانات في صورة جدول، ويمكن فتحه باستخدام برامج مثل Excel أو Google Sheets.

**ملحوظة:** التحليلات في الإصدار الحالي تعتمد على عدد الوحدات المباعة، وليس الأموال أو الأرباح. التطبيق لا يخزن أسعار المنتجات في هذا الإصدار، وبالتالي لا يحسب الإيرادات.

### 4.5 Demand Forecast — التنبؤ بالطلب

**المسار:** Sidebar → Forecasting → Demand Forecast

هذه هي ميزة الذكاء الاصطناعي الأساسية في المشروع.

تستخدم بيانات المبيعات السابقة لتقدير عدد الوحدات المتوقع بيعها خلال الأيام القادمة.

#### طريقة الاستخدام

1. اختر المنتج.
2. اختر الفترة المستقبلية التي تريد التوقع لها:
   - Next 7 Days.
   - Next 14 Days.
   - Next 30 Days.
3. اضغط Generate Forecast.

#### ماذا ستجد في النتيجة؟

- شارة **Estimate** صفراء — الأصفر في التطبيق يعني دائمًا "تقدير/احتياط": هذه أرقام تقديرية وليست وعدًا مضمونًا.
- إجمالي الطلب المتوقع خلال الفترة.
- متوسط الطلب المتوقع يوميًا.
- جدول يعرض التوقعات لكل يوم.
- الطريقة التي استخدمها التطبيق لإنتاج التوقع.

#### ما الطرق المستخدمة في التوقع؟

يعتمد التطبيق على مقدار البيانات التاريخية المتاحة للمنتج:

| البيانات المتاحة | الطريقة | شرح مبسط |
|---|---|---|
| 31 يومًا أو أكثر | Random Forest Model | نموذج Machine Learning مدرب على بيانات المبيعات، ويستفيد من أنماط مثل أيام الأسبوع ومتوسطات المبيعات الأخيرة. |
| من يوم إلى 30 يومًا | Trailing 7-Day Average | متوسط مبيعات آخر 7 أيام، ويستخدم كطريقة أبسط عندما تكون البيانات قليلة. |
| لا توجد أيام مسجلة | No Forecast | لا ينتج التطبيق توقعًا، لأنه لا يملك بيانات كافية يعتمد عليها. |

**ما هو Random Forest؟**

هو Algorithm (خوارزمية، أي طريقة حسابية لحل مشكلة معينة) من خوارزميات Machine Learning.

في مشروعنا، يستخدم بيانات المبيعات السابقة لاكتشاف الأنماط التي قد تساعده على تقدير المبيعات المستقبلية.

#### شرط مهم قبل عمل Forecast

ليس كل منتج يمكن عمل توقع له مباشرة.

يجب أولًا ربط المنتج ببياناته التاريخية المستوردة.

الخطوات:

1. افتح Products & Inventory.
2. انتقل إلى Edit Product.
3. فعّل الاختيار Forecast via a linked dataset item.
4. أدخل رقم Dataset Item المطابق لهذا المنتج.

بعد الربط، يستطيع التطبيق استخدام المبيعات التاريخية الخاصة بهذا الرقم في التوقع.

#### كيف أعرف دقة النموذج؟

يوجد في أسفل صفحة Forecast قسم يعرض نتائج تقييم النموذج.

ستجد مقياسين أساسيين:

- **MAE (Mean Absolute Error):** متوسط الفرق المطلق بين القيمة الحقيقية والقيمة التي توقعها النموذج. يتم قياسه بعدد الوحدات، وكلما كان أقل كانت التوقعات أفضل.
- **RMSE (Root Mean Squared Error):** مقياس للخطأ يشبه MAE، لكنه يعطي وزنًا أكبر للأخطاء الكبيرة.

وفقًا لنتائج التقييم المسجلة في الإصدار الحالي:

- متوسط خطأ النموذج حوالي 6 وحدات لكل منتج في اليوم.
- الطريقة البسيطة التي تكرر آخر قيمة حققت خطأ حوالي 10.5 وحدات.
- المتوسط الأسبوعي البسيط حقق خطأ حوالي 8.4 وحدات.

هذا يعني أن النموذج حقق نتائج أفضل من طرق المقارنة البسيطة في التقييم الذي تم إجراؤه.

هذه الأرقام هي نتائج تقييم محفوظة من مرحلة التدريب، وليست حسابات يتم تحديثها مباشرة مع كل عملية توقع.

وتذكر دائمًا: التوقع تقدير مبني على البيانات، وليس ضمانًا للمبيعات المستقبلية.

### 4.6 Data Import — استيراد البيانات التاريخية

**المسار:** Sidebar → Data → Data Import

هذه الصفحة تسمح لك بإدخال بيانات مبيعات قديمة موجودة في ملفات Excel أو CSV أو أنظمة أخرى.

الهدف الأساسي من استيراد هذه البيانات هو توفير تاريخ مبيعات كافٍ لتحليل المنتجات وتدريب واستخدام نموذج التوقعات.

#### أولًا: شكل ملف CSV المطلوب

التطبيق يتوقع أربعة أعمدة بالضبط، وبالأسماء التالية:

```csv
date,store,item,sales
2016-01-01,1,1,12
2016-01-02,1,1,9
```

شرح الأعمدة:

| العمود | معناه |
|---|---|
| date | تاريخ حدوث البيع، بالصيغة `YYYY-MM-DD`. |
| store | رقم المتجر. التطبيق مصمم حاليًا للعمل مع متجر واحد، لذلك يستورد بيانات Store 1 فقط. |
| item | رقم المنتج داخل Dataset. |
| sales | عدد الوحدات التي تم بيعها في هذا اليوم. يجب ألا تكون قيمة سالبة. |

لا يسمح التطبيق بإضافة أعمدة أخرى أو حذف أي عمود من الأعمدة المطلوبة.

#### ثانيًا: ماذا يحدث عند رفع الملف؟

عملية الاستيراد تمر بعدة خطوات، والأهم أن البيانات لا يتم حفظها بمجرد رفع الملف.

**الخطوة 1: Upload**

ترفع ملف CSV من خلال الصفحة.

**الخطوة 2: Validation**

يبدأ التطبيق في فحص الملف والتأكد من صحة البيانات.

**ما معنى Validation؟**

يعني التحقق من أن البيانات سليمة وتطابق الشروط المطلوبة قبل قبولها.

مثلًا:

- هل الأعمدة المطلوبة موجودة؟
- هل التاريخ مكتوب بشكل صحيح؟
- هل المبيعات أرقام غير سالبة؟
- هل توجد بيانات ناقصة؟
- هل توجد سجلات مكررة؟

بعد الفحص، يعرض التطبيق Preview، أي معاينة للبيانات قبل حفظها.

ستجد معلومات مثل:

- عدد الصفوف الموجودة في الملف.
- عدد الصفوف الصالحة الخاصة بـ Store 1.
- عدد الصفوف المرفوضة.
- عدد الصفوف التابعة لمتاجر أخرى.
- الفترة الزمنية التي تغطيها البيانات.
- عينة من السجلات المقبولة.

**الخطوة 3: مراجعة الأخطاء**

يمكنك فتح الأقسام الخاصة بالصفوف المرفوضة والتكرارات لمعرفة المشكلة.

يعرض التطبيق رقم الصف وسبب المشكلة، مثل:

- تاريخ غير صالح.
- قيمة مبيعات سالبة.
- بيانات ناقصة.
- تكرار نفس المنتج ونفس التاريخ.

**الخطوة 4: Import**

إذا كانت البيانات صالحة، يمكنك الضغط على زر:

Import N record(s)

هنا فقط يبدأ حفظ البيانات داخل قاعدة البيانات.

#### كيف يتم حفظ البيانات؟

التطبيق يستخدم Transaction أثناء عملية الاستيراد.

**ما معنى Transaction؟**

هي طريقة لتنفيذ مجموعة من عمليات الحفظ كوحدة واحدة.

بمعنى أبسط:

- إما أن يتم حفظ كل السجلات المقبولة بنجاح.
- أو يتم إلغاء العملية بالكامل إذا حدثت مشكلة.

لا نريد أن يتم حفظ نصف البيانات فقط وترك النصف الآخر، لأن ذلك قد يؤدي إلى نتائج غير صحيحة.

بعد نجاح العملية، يعرض التطبيق ملخصًا يوضح:

- عدد السجلات التي تم حفظها.
- عدد السجلات التي تم تخطيها.
- رقم عملية الاستيراد Batch Number.

**ما معنى Batch؟**

هي عملية استيراد واحدة. كل مرة تستورد فيها ملفًا بنجاح، يتم تسجيل عملية جديدة برقم يمكن الرجوع إليه.

ويمكنك فتح Previous Imports لمراجعة عمليات الاستيراد السابقة.

#### كيف يمنع التطبيق استيراد نفس الملف مرتين؟

يستخدم التطبيق Fingerprint.

**ما معنى Fingerprint؟**

هو بصمة رقمية للملف، يتم حسابها باستخدام محتواه.

تساعد هذه البصمة التطبيق على التعرف على الملف إذا حاول المستخدم رفع نفس الملف مرة أخرى.

إذا رفعت نفس الملف الذي تم استيراده بالكامل من قبل، سيرفض التطبيق استيراده مرة ثانية حتى لا يتم احتساب نفس المبيعات مرتين.

أما إذا رفعت ملفًا مختلفًا يحتوي على بيانات جديدة وبعض البيانات القديمة، فيمكن للتطبيق استيراد السجلات الجديدة فقط وتجنب التكرارات.

#### أهم نقطة: هل استيراد البيانات يغير المخزون؟

لا.

**Data Import لا يغير Current Stock نهائيًا.**

البيانات المستوردة هي Historical Sales، أي سجل المبيعات التاريخية، وتُستخدم في التحليل والتوقعات فقط.

أما المخزون الحالي فيتم تغييره من خلال تسجيل المبيعات أو استخدام Adjust Stock.

لا تخلط بين بيانات المبيعات التاريخية والكمية الموجودة حاليًا في المتجر.

### 4.7 Restocking Recommendations — اقتراحات إعادة التخزين

**المسار:** Sidebar → Inventory → Restocking Recommendations

هذه الصفحة تحول بيانات المبيعات والمخزون إلى اقتراحات تساعدك على تحديد المنتجات التي تحتاج إلى إعادة طلب.

**مهم:** هذه الصفحة تقدم Recommendations فقط. لا يتم تنفيذ أي طلب شراء ولا يتم تغيير المخزون تلقائيًا.

#### البطاقات الموجودة في الأعلى

تعرض:

- عدد المنتجات التي تحتاج إلى إعادة تخزين.
- عدد المنتجات التي تتوفر لها توصيات يمكن استخدامها.
- عدد المنتجات التي لا تتوفر لها بيانات كافية بعد.

#### Consider Restocking

هذا الجدول يعرض المنتجات التي وصلت إلى Reorder Point أو أصبحت أقل منه.

لكل منتج يعرض معلومات مثل:

- Stock: الكمية الموجودة حاليًا.
- Average Daily Demand: متوسط الطلب اليومي.
- Lead Time: مدة وصول الطلب.
- Safety Stock: المخزون الاحتياطي.
- Reorder Point: الحد الذي عنده يجب التفكير في إعادة الطلب.
- Target Stock: الكمية المستهدفة بعد إعادة التخزين.
- Order: عدد الوحدات المقترح طلبها.

**التوصية بالتفصيل:** لكل منتج يوجد expander يفتح شرح الحساب كاملًا. يبدأ الـ expander برقم الطلب المقترح بخط كبير وبلون برتقالي (البرتقالي في التطبيق يعني "يحتاج انتباه")، ثم تعرض خطوات الحساب في لوحة خط أحادي المسافة حتى يسهل التمييز بين الحساب والشرح النصي — لتتحقق من الاقتراح بنفسك بدل الوثوق به بشكل أعمى.

#### كيف يفكر التطبيق في حساب الكميات؟

التطبيق يستخدم ثلاث معادلات أساسية:

**1. Reorder Point**

```text
Reorder Point =
(Average Daily Demand × Lead Time) + Safety Stock
```

أي أن نقطة إعادة الطلب تساوي متوسط الطلب اليومي مضروبًا في مدة وصول الشحنة، ثم نضيف المخزون الاحتياطي.

**2. Target Stock**

```text
Target Stock =
(Average Daily Demand × (Lead Time + 7)) + Safety Stock
```

أي أن الكمية المستهدفة تغطي فترة وصول الشحنة، بالإضافة إلى احتياطي يغطي 7 أيام أخرى.

**3. Order Quantity**

```text
Order Quantity = Target Stock - Current Stock
```

إذا كانت النتيجة سالبة، يعرض التطبيق صفرًا بدلًا من كمية سالبة.

#### مثال عملي

لنفترض أن:

- المنتج يبيع 3 وحدات يوميًا.
- مدة وصول الشحنة 5 أيام.
- Safety Stock يساوي 10 وحدات.

الحساب:

**Reorder Point:**

```text
3 × 5 + 10 = 25
```

عندما يصل المخزون إلى 25 وحدة أو أقل، يجب التفكير في إعادة الطلب.

**Target Stock:**

```text
3 × (5 + 7) + 10 = 46
```

إذن الكمية المستهدفة هي 46 وحدة.

إذا كان المخزون الحالي 20 وحدة:

```text
46 - 20 = 26
```

إذن التطبيق سيقترح طلب 26 وحدة.

#### لماذا قد لا تظهر توصية لبعض المنتجات؟

يحتاج المنتج إلى وجود عملية بيع مسجلة واحدة على الأقل حتى يستطيع التطبيق حساب متوسط الطلب اليومي.

إذا لم توجد مبيعات مسجلة للمنتج، سيظهر ضمن Not Available Yet مع توضيح السبب.

#### تنزيل التوصيات

يمكنك الضغط على:

Export Recommendations (CSV)

لتنزيل جدول التوصيات في ملف CSV واستخدامه مع المورد أو في برنامج جداول البيانات.

## 5. مهام شائعة خطوة بخطوة

### 5.1 تجهيز المتجر لأول مرة

1. افتح Products & Inventory ثم Add Product.
2. أضف كل منتج باستخدام SKU مختلف، وحدد كمية المخزون الحالية.
3. أدخل Lead Time وSafety Stock بقيم واقعية.
4. إذا كان لديك سجل مبيعات قديم في ملف CSV، استورده من Data Import.
5. افتح Edit Product واربط كل منتج برقم Dataset Item المطابق له إذا كنت تريد استخدام التوقعات.
6. ابدأ تسجيل المبيعات اليومية من Sales Management.

### 5.2 حدثت عملية بيع جديدة

1. افتح Sales Management.
2. اختر Record Sale.
3. اختر المنتج.
4. أدخل الكمية والتاريخ.
5. اضغط Record Sale.

سيتم تسجيل البيع وخصم الكمية من المخزون تلقائيًا.

### 5.3 وصلت شحنة جديدة

1. افتح Products & Inventory.
2. اختر Adjust Stock.
3. اختر Add or Remove Units.
4. أدخل عدد الوحدات التي وصلت كرقم موجب.
5. اضغط Apply Adjustment.

### 5.4 اكتشفت أن كمية المخزون غير صحيحة

1. قم بعدّ الكمية الموجودة فعليًا.
2. افتح Products & Inventory.
3. اختر Adjust Stock.
4. اختر Set Exact Stock (Correction).
5. أدخل الكمية الصحيحة.
6. اضغط Set Stock Level.

استخدم هذه الطريقة لتصحيح العدد الفعلي فقط، وليس للتعديلات اليومية العادية.

### 5.5 هل يجب أن أطلب منتجات اليوم؟

1. افتح Dashboard وراجع Products Needing Reorder.
2. افتح Restocking Recommendations.
3. راجع المنتجات والكميات المقترحة.
4. اقرأ شرح الحساب الخاص بكل منتج.
5. اتخذ قرار الشراء بنفسك.
6. عندما تصل الشحنة، سجل الكمية الجديدة من خلال Adjust Stock.

### 5.6 لماذا لا أستطيع عمل Forecast لمنتج معين؟

راجع الخطوات التالية بالترتيب:

1. هل المنتج مرتبط بـ Dataset Item؟ راجع Edit Product.
2. هل تم استيراد بيانات المبيعات التاريخية لهذا الرقم؟ راجع Data Import ثم Previous Imports.
3. هل يوجد يوم واحد على الأقل من بيانات المبيعات لهذا المنتج؟
4. هل تم تدريب Model؟ راجع طريقة التدريب في القسم 2.5.

إذا لم يتحقق أحد الشروط المطلوبة، فلن يستطيع التطبيق إنتاج التوقع المناسب.

## 6. القواعد التي يطبقها النظام

هذه القواعد موجودة لحماية البيانات ومنع حدوث أخطاء في المخزون والمبيعات.

| إذا حاول المستخدم... | ماذا يفعل التطبيق؟ | السبب |
|---|---|---|
| بيع كمية أكبر من المخزون المتاح | يرفض عملية البيع بالكامل | حتى لا يصبح المخزون بالسالب ولا يتم تسجيل بيع غير ممكن. |
| بيع منتج تم إيقافه | يرفض العملية | المنتجات غير النشطة لا يمكن بيعها، لكن سجلها القديم يظل محفوظًا. |
| تسجيل عملية بيع بتاريخ مستقبلي | يرفض العملية | يتم تسجيل المبيعات التي حدثت بالفعل فقط. |
| تسجيل كمية بيع صفر أو أقل | يرفض العملية | لا تعتبر هذه عملية بيع صحيحة. |
| تعديل المخزون إلى قيمة سالبة | يرفض التعديل | المخزون لا يمكن أن يكون أقل من صفر. |
| حذف منتج | يستخدم Soft Delete | للحفاظ على تاريخ المنتج وإمكانية إعادة تفعيله. |
| استيراد CSV بأعمدة خاطئة أو بيانات غير سليمة | يرفض الصفوف غير الصالحة ويوضح الأسباب | حتى لا تدخل بيانات غير صحيحة إلى النظام. |
| استيراد نفس الملف مرتين | يرفض الاستيراد الثاني | لمنع تكرار احتساب المبيعات. |
| حساب الإيرادات والأرباح | لا يوفر هذه الميزة | لأن الإصدار الحالي لا يخزن أسعار المنتجات. |

## 7. فهم رسائل التطبيق

التطبيق يستخدم ألوانًا مختلفة لتوضيح نتيجة العمليات:

| نوع الرسالة | معناها |
|---|---|
| Green Confirmation | العملية نجحت، والرسالة توضح ما الذي تم تغييره. |
| Orange / Yellow Warning | يوجد شيء يحتاج إلى انتباه، لكن لا توجد مشكلة تمنع استخدام التطبيق. مثال: انخفاض المخزون. الأصفر تحديدًا يشير إلى **تقديرات**: أرقام التنبؤ والقيم الاستشارية. |
| Red Error | العملية لم يتم تنفيذها. يجب إصلاح المشكلة والمحاولة مرة أخرى. |
| Blue Info | معلومة أو توضيح إضافي، مثل سبب عدم إمكانية التنبؤ لمنتج معين. |

**قاعدة مهمة جدًا:**

إذا ظهرت رسالة خطأ باللون الأحمر، فهذا يعني أن العملية لم يتم تنفيذها ولم يتم حفظ تغيير جزئي في البيانات.

نص الرسائل نفسه يتبع لغة الواجهة: عند اختيار اللغة العربية من الشريط
الجانبي، تظهر رسائل التحقق وشروحات المخزون وأسماء الحالات بالعربية
(وتبقى الرموز التقنية — رموز المنتج SKU والتواريخ ومراجع DEC-xxx
بالأرقام والصيغة الغربية).

## 8. الأسئلة الشائعة (FAQ)

### هل يستطيع التطبيق طلب المنتجات من الموردين تلقائيًا؟

لا. التطبيق يقدم اقتراحات فقط، والمستخدم هو الذي يقرر ويقوم بالشراء بنفسه.

### هل يمكنني إدارة أكثر من متجر أو فرع؟

لا في الإصدار الحالي.

التطبيق مصمم للعمل مع متجر واحد فقط، ويستورد بيانات Store 1 من ملفات المبيعات التاريخية.

### هل يمكنني التراجع عن عملية بيع؟

لا يمكن تعديل أو حذف سجلات المبيعات.

إذا تم تسجيل عملية بيع بالخطأ، يمكنك تصحيح كمية المخزون من خلال Adjust Stock في صفحة Products & Inventory.

لكن يجب الانتباه إلى أن تصحيح المخزون لا يحذف سجل البيع الخاطئ من التاريخ.

### لماذا يظهر لي Trailing 7-Day Average Fallback؟

يظهر ذلك عندما يكون المنتج لديه أقل من 31 يومًا من البيانات التاريخية.

في هذه الحالة، لا يستخدم التطبيق Random Forest Model، بل يعتمد على متوسط آخر 7 أيام باعتباره طريقة أبسط للتوقع.

عندما تتوفر 31 يومًا أو أكثر من البيانات، يستطيع التطبيق استخدام Random Forest تلقائيًا.

### هل أرقام دقة النموذج يتم حسابها في كل مرة أعمل فيها Forecast؟

لا.

الأرقام المعروضة هي نتائج التقييم التي تم تسجيلها أثناء تدريب النموذج، ويتم عرضها كما هي.

### أين أجد أسعار المنتجات والأرباح؟

هذه الميزة غير موجودة في الإصدار الحالي.

التطبيق يتعامل مع الكميات والوحدات المباعة فقط، ولا يخزن أسعار المنتجات، لذلك لا يحسب الإيرادات أو الأرباح.

### هل يتم إرسال بياناتي إلى الإنترنت؟

لا.

التطبيق يعمل على جهازك، ويحفظ البيانات داخل ملف قاعدة البيانات المحلي:

`data/smartstock.db`

لا يتم إرسال بيانات التطبيق إلى خدمة خارجية حسب طريقة عمل الإصدار الحالي.

### زر Forecast يقول إن Model Artifact غير موجود. ماذا أفعل؟

هذا يعني أن نموذج Machine Learning لم يتم تدريبه على نسخة المشروع الموجودة لديك، أو أن ملف النموذج الناتج عن التدريب غير موجود.

راجع القسم 2.5 ونفذ أمر تدريب النموذج.

## 9. قاموس المصطلحات (Glossary)

| المصطلح | الشرح |
|---|---|
| MAE | Mean Absolute Error: متوسط مقدار الخطأ بين التوقعات والقيم الحقيقية. كلما كان أقل كانت النتائج أفضل. |
| RMSE | Root Mean Squared Error: مقياس للخطأ يعطي تأثيرًا أكبر للأخطاء الكبيرة مقارنة بـ MAE. |
| Baseline | طريقة بسيطة نستخدمها للمقارنة مع نموذج Machine Learning، مثل افتراض أن مبيعات الأسبوع القادم ستكون مثل الأسبوع الماضي. |
| Soft Delete | إيقاف أو إخفاء السجل بدلًا من حذفه نهائيًا، مع الاحتفاظ ببياناته وإمكانية استعادته. |
| Batch | عملية استيراد واحدة للبيانات، ويكون لها رقم مميز. |
| Fingerprint | بصمة رقمية للملف تساعد التطبيق على التعرف على الملف الذي تم استيراده من قبل. |
| CSV | ملف يحتوي على بيانات منظمة في صورة صفوف وأعمدة، ويمكن فتحه ببرامج الجداول مثل Excel. |
| Database | قاعدة بيانات: مكان منظم يتم فيه حفظ المعلومات حتى يستطيع التطبيق الرجوع إليها وتحديثها. |
| SQLite | نظام قاعدة بيانات بسيط يخزن البيانات داخل ملف واحد. |
| Storage | التخزين: المكان الذي يتم فيه الاحتفاظ بالبيانات والملفات. |
| Backup | نسخة احتياطية من البيانات، نحتفظ بها حتى نستطيع استعادة المعلومات عند حدوث مشكلة. |
| Transaction | مجموعة عمليات حفظ يتم تنفيذها كوحدة واحدة؛ إما تنجح كلها أو يتم إلغاؤها كلها. |
| Validation | التحقق من صحة البيانات قبل قبولها أو حفظها. |
| Preview | معاينة البيانات قبل تنفيذ عملية الاستيراد. |
| Model | نموذج تعلم آلي يتعلم من البيانات ويستخدم ما تعلمه لإنتاج توقعات. |
| Machine Learning | تعلم الآلة: مجال من الذكاء الاصطناعي يسمح للبرنامج بالتعلم من البيانات واكتشاف الأنماط. |
| Algorithm | خوارزمية: مجموعة خطوات أو قواعد لحل مشكلة أو تنفيذ عملية حسابية. |
| Forecast | توقع مبني على البيانات السابقة. |
| Forecast Horizon | المدة المستقبلية التي نريد عمل توقع لها. |
| Localhost | عنوان يشير إلى التطبيق الذي يعمل على نفس جهاز الكمبيوتر. |
| venv | بيئة افتراضية منفصلة لمكتبات Python الخاصة بالمشروع. |
| Dependency | مكتبة أو أداة يعتمد عليها المشروع حتى يعمل بشكل صحيح. |
| Export | تصدير البيانات إلى ملف يمكن استخدامه خارج التطبيق. |
| Import | استيراد البيانات من ملف خارجي إلى التطبيق. |
